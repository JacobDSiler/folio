The monetization strategy — read this first

Phase 1 — Closed testing (this week)

TWA JavaScript is set to MODE = 'safe'. Inside the Android app, subscribe/upgrade buttons are hidden entirely and replaced with a small notice telling users to visit onfolio.press to see plans. On the web, everything works exactly as it always has.

Result: Zero Play policy risk. No revenue path in the app = nothing for Play to enforce against. Closed testing goes through cleanly.

Phase 2 — After Reader App approval (2–3 weeks out)

Flip MODE = 'reader' in folio-twa.js, redeploy, rebuild AAB with a bumped version code, publish. Subscribe buttons come back — but now they open in the user's external browser (not the TWA container, not Chrome Custom Tabs) and appear with the required disclosure text. PayPal keeps working. No Play Store cut.

What we're NOT doing

No Google Play Billing integration. That would require moving off TWA to a hybrid shell (Capacitor) and integrating the Play Billing SDK — a large piece of native work. The Reader App exception exists precisely so book/media apps don't have to. If Reader status is denied, we'll reassess then.

Answer to your question: Yes — the disclosure text is app-only. The JavaScript detects TWA mode and only shows it inside the wrapper. Web visitors never see any of it. And you're right that redirecting to the browser is the play; the module handles this with an intent:// link that forces the external browser (not Chrome Custom Tabs, which Google's policy treats ambiguously).

Step 3 — Fix the CNAME file

Your CNAME at the repo root has markdown link syntax ([www.onfolio.press](https://www.onfolio.press)) instead of just the hostname. GitHub Pages / Cloudflare Pages expect a single line with just the domain.

Step 8 — Upload AAB → Closed testing

  1. Testing → Closed testing. Create new track "Alpha" (or reuse your existing).
  2. Testers tab → Create email list → add your Gmail + friends. 12+ testers for 14 continuous days is required before promoting to production on a new personal account (doesn't block closed testing).
  3. Releases tab → Create new release → upload app-release-bundle.aab. Play will warn about URL handling / assetlinks — expected, fixed in Step 9.
  4. Release name: 1 (1.0.0). Notes: Initial release.
  5. Save → Review release → Start rollout. Google review: 1–3 days for first submission on a personal account.
  6. After review, testers tab gives you an opt-in URL. Open on Redmi in Chrome → "Become a tester" → Play Store link → install. Done.

Step 9 — Publish assetlinks.json

Once AAB is uploaded, Play Console shows the App Signing SHA-256:

Setup → App integrity → App signing key certificate → SHA-256 certificate fingerprint. Copy it.

Your upload key SHA-256 is in the auto-generated assetlinks.json Bubblewrap made in the project directory. Grab it there.

Combine both into the template file I gave you, then host at:

https://onfolio.press/.well-known/assetlinks.json

Create .well-known/ folder at repo root, drop the file, deploy. Verify with Google's Asset Links tester. Without this, users see a browser URL bar on the app. Everything else works.

Step 10 — Submit Reader App application

Once your closed-testing release is live in Play, submit the Reader Apps application. I've drafted the whole thing — see reader-app-application.md. Submit at:

https://support.google.com/googleplay/android-developer/answer/12570971

Review time: typically 7–21 days.
