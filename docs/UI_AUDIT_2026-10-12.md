# Folio UI Audit — 2026-10-12

Pre-tutorial-video UX pass. Scope: homepage, app.html top-level chrome + tabs + release modal + sidebar, shelf, guild, imprint, press, admin. Toolbar Release/Print split (fixed today) is intentionally not flagged.

---

## 1. Executive summary

Three themes dominate the findings, in order of impact:

1. **Vocabulary drift between surfaces.** The same action is called Release / Publish / Ship / "Release this Folio" / 🔖 Publish within one modal and across five pages. "Format / Narrate / Release" (homepage), "Design / Produce / Ship" (app tabs), "Set type / Narrate / Release" (how-it-works) all describe the same four stages with three different vocabularies. Pick one and apply everywhere before filming.
2. **The release modal is the single highest-friction surface.** It's the hero flow for the hero video, and today it mixes free + paid + shelf-listing + series + attestation + rights + Ink + webhooks in one scroll. The fill order jumps across concern boundaries (Title → paid-only URL slug → Access → Shelf → Content rating → Universe). The paid-mode block drops a huge walkthrough directly above Price / Currency. Easy wins by rearranging + progressively disclosing paid-only sections.
3. **Help/tutorial discoverability is scattered.** There are three help entry points (Shortcuts → Help + FAQ, bottom-sidebar "🎬 New here? Tutorials" chip, and Guided tour under Write). Two of the three sit inside collapsible panels. A new user hunting for "where do I start?" has nothing obvious at eye level.

## 2. Priority Tier 1 — fix before filming the hero video

### T1-1. Rename the primary publish button inside the release modal from "🔖 Publish" to "🔖 Release"
- **Where:** `app.html` L37780 (`#rlPublishBtn`), modal title L36651 already reads *"🔖 Release this Folio"*, sidebar button L7533 reads *"Release…"*, toolbar button L8259 reads *"🔖 Release"*.
- **Why:** The modal is called *Release*, the sidebar button is *Release*, the toolbar is *Release* — but the primary call-to-action inside the modal is *Publish*. On film, "click Release → click Publish" invites "wait, which one actually publishes?" from viewers.
- **Fix:** Change button label to **"🔖 Release"** (and `#rlUnpublishBtn` to **"Unrelease"** or **"Take down"**). Keep the function name `_rlPublish`.
- **Impact:** High.

### T1-2. Rename the Ship → "☁ Folio" sub-tab
- **Where:** `app.html` L6859. Button literally reads *"☁ Folio"* inside the Folio app.
- **Why:** A tab called *Folio* inside the Folio app is a semantic black hole. The cloud icon suggests this is sync/cloud status. In reality it's project settings (visibility, custom URL, SEO, ownership). The confusion is on-camera-visible from the first second a viewer lands on the Ship tab.
- **Fix:** Rename to **"⚙ Settings"** or **"⚙ This folio"** and keep the legacy `switchTab('folio', …)` id for backwards compat.
- **Impact:** High.

### T1-3. "Customize imprint" sidebar tile opens a NEW TAB instead of using the in-app drawer
- **Where:** `app.html` L6483 (`imprintCustomizeBtn`). Inline onclick calls `window.open('/imprint/?uid=' + uid + '&customize=1', '_blank')`.
- **Why:** The imprint page already has a native customize drawer (`imprint/index.html` L1127 `#customizeToggle`, drawer at L1129). Opening a new tab for an action that could be a drawer breaks flow — the user's draft is now out-of-focus and the back button doesn't return them to work. On video this looks like Folio can't customize its own branding without a page jump.
- **Fix:** Either (a) open the imprint page in the same tab, or (b) load the customize drawer markup inside app.html and open it in place; (c) if same-tab is deemed too jarring, at least make it `target="_blank"` cleanly without the inline fallback alert `"Sign in first, then click Customize again."` (which is itself a dead-end: it tells users what to do but gives them no way back).
- **Impact:** High.

### T1-4. The paid-mode walkthrough visually buries Price / Currency
- **Where:** `app.html` L36801 onward — the "Auto-deliver unlock links" `<details>` + its ~130-line Ko-fi/Payhip/PayPal walkthroughs sit directly between the vendor picker and the Price / Currency inputs (L36978). A first-time author selecting *Paid* sees a wall of help text before they see the price field.
- **Fix:** Move Price + Currency to directly after vendor pick, and keep the auto-deliver walkthrough collapsed (it already is) and placed *below* the price fields. "What am I selling and for how much" should always come before "how do I wire my webhook".
- **Impact:** High.

### T1-5. The "Access" picker — only one of three mode buttons uses an emoji
- **Where:** `app.html` L36697–L36705. Buttons: *"Public & free"* (no icon), *"💳 Paid"*, *"Private link"* (no icon).
- **Why:** The asymmetric emoji makes "Paid" visually dominant even though it's the lowest-volume path for a new user. On a thumbnail the eye jumps to 💳 first.
- **Fix:** Either put an icon on all three (🌐 Public & free · 💳 Paid · 🔒 Private link) or remove the 💳. Order matters too — most users want *Public & free* first; it's already the leftmost but should be the visually dominant default state (bordered-active on open).
- **Impact:** Medium–High.

### T1-6. Homepage pricing table footer says "Free → $9/mo" — doesn't match the actual $5/$12 tiers
- **Where:** `index.html` L1213 — compare-table header reads *"Folio — Free → $9/mo"*. Press subscription tiers are $5 (Indie) and $12 (Imprint) in both `index.html` L1161/L1178 and `press/index.html` L215/L240. There is no $9 tier.
- **Fix:** Change to "Free → $5–$12/mo" (or just "Free → $5/mo") to match reality. If this is a legacy value, grep for other $9 references.
- **Impact:** High (credibility — pricing mismatch is the easiest "aged content" moment in a tutorial).

### T1-7. Homepage says Custom subdomain is "coming soon"; Press says it ships today
- **Where:** `index.html` L1183 — Imprint tier bullet reads *"Custom subdomain (coming soon)"*. `press/index.html` L254 lists *"Custom subdomain — yourname.onfolio.press as your imprint's short link"* as a shipped feature.
- **Fix:** Pick one and sync both. If it's live, drop the "(coming soon)". If not, add it to Press.
- **Impact:** Medium–High.

### T1-8. The "Current Folio" section's "Save" button is disabled on first load with no explanation
- **Where:** `app.html` L7498 — `<button id="btnSaveProj" … disabled>Save</button>`.
- **Why:** New users land in the editor, see a disabled Save button, don't know why. The adjacent "Not saved" badge (L7490) just reinforces anxiety.
- **Fix:** Either keep it enabled and show a toast on click ("Give your folio a name first — type it in the field above"), or add inline helper copy under the input such as *"Name your folio and the Save button lights up."*
- **Impact:** Medium.

### T1-9. "New here? Tutorials" lives as an 11px chip at the bottom of the sidebar
- **Where:** `app.html` L7954. Dark bar at the bottom with four other chips (Guild, Ink, Support Folio, Try Folio Press). All competing for the same 11px line.
- **Why:** This is the single most important link for a new user; it's currently the smallest, lowest-contrast element in the sidebar. "Where are the tutorials?" will be the first search in the YouTube comments.
- **Fix:** Promote it. Either (a) a bordered pill at the TOP of the sidebar for first-session users (reads "New here? Watch the 3-minute tour →"), auto-dismissible, or (b) at minimum move it above the fold and give it the same visual weight as *Try Folio Press* (filled accent, not ghost).
- **Impact:** High for new users; medium overall.

### T1-10. Workspace preset picker tooltip exposes internal doc path
- **Where:** `app.html` L6442 — `title="Workspace layout — see docs/MODULAR_UI_PLAN.md"`.
- **Why:** Reader-facing tooltip references an internal planning doc. Pure sloppiness; nothing a tutorial viewer should see.
- **Fix:** Change to *"Workspace layout — Full, Write, or Focus mode"* (same copy as the options themselves).
- **Impact:** Low on its own, but zero-effort fix and avoids a cringe moment if a video happens to zoom in.

## 3. Priority Tier 2 — fix after the hero video, before the full batch

### T2-1. Three different names for the four-stage pipeline
- Homepage features: **Write · Format · Narrate · Release** (`index.html` L941/948/955/962).
- Homepage "how it works": **Draft · Set type · Narrate · Release** (L979-982).
- App tabs: **✍ Write · 🎨 Design · 🎧 Produce · 📤 Ship** (`app.html` L6847-L6850).
- App header subtitle: *"Format · Export · Collaborate — PDF · EPUB · MD · and more"* (L6431).
- **Fix:** Canonicalise. Suggest **Write · Design · Produce · Release** (keep app tabs' names, swap "Ship" for "Release" to match the primary CTA term, and apply those four everywhere).

### T2-2. "The Folio Shelf" vs "The Shelf" vs "/shelf"
- `app.html` L6475 *"The Folio Shelf"*; L8310 *"Browse The Shelf"*; `shelf.html` L255 *"The Folio Shelf"*. Even on the homepage: *"Browse the full Shelf"* L1011 vs section tag *"Shelf"* L990.
- **Fix:** Pick **"The Folio Shelf"** on first use per screen and **"the Shelf"** thereafter. Grep for `>Shelf</` and align.

### T2-3. "Customize imprint" / "Customize this imprint" / "Customize my imprint" (3 wordings for one button)
- `app.html` L6488 (sidebar) *"Customize imprint"*; `imprint/index.html` L1127 *"🎨 Customize this imprint"*; L595 (owner-only CTA) *"🎨 Customize my imprint"*.
- **Fix:** Pick one. Suggest **"Customize imprint"** everywhere (parallels "Customize imprint" plural-neutral; and viewers in the audience are already thinking in the second person).

### T2-4. Papermint sidebar link siphons attention mid-draft
- **Where:** `app.html` L6508 — Papermint cross-promo link in the sidebar shortcuts, `target="_blank"`.
- **Why:** Papermint is a *companion* product. Giving it the same visual weight as *Customize imprint* and *Product photos* trains the eye to treat it as a core feature. First-time users will click it, land on an entirely different site, and come back wondering what Folio actually does.
- **Fix:** Move it under a *"More tools"* disclosure, or collapse into a small footer-link cluster next to Ink. Keep discovery; demote visual weight.

### T2-5. Guild genre list doesn't match Shelf/Release genre list
- **Where:** `guild/index.html` L131-136 (also L172-177 and L202-207) uses *"Mystery / Thriller"* as one option, no *"Science fiction"* capitalisation match, no *"Educational / How-to"*. Shelf (`shelf.html` L292-300) and release modal (`app.html` L37081-L37097) both split *"Mystery / Crime"* and *"Thriller / Suspense"* and include Educational.
- **Fix:** Share the taxonomy. Lift from `docs/folio-taxonomy.json` (already referenced in `rlClassifyPrimary`) in Guild as well.

### T2-6. Shelf primary-genre dropdown on Guild listing defaults to "Literary fiction"
- **Where:** `guild/index.html` L202 — `<select id="mGenre">` first option is *"Literary fiction"* (not a prompt).
- **Fix:** Prepend `<option value="" disabled selected>Pick a genre…</option>` so users can't silently save a listing mis-tagged.

### T2-7. Nav "Sign in" button on homepage just goes to the editor, not sign-in
- **Where:** `index.html` L795 — `<a class="btn ghost tiny" href="app.html">Sign in</a>`. Identical destination to L796 *"Start writing — free"*.
- **Why:** Returning users click Sign in expecting a Google popup; they get the editor's splash (which does trigger GIS, but only after a sidebar click).
- **Fix:** Add `?signin=1` to the sign-in href, and have `app.html` kick the Google flow immediately when that param is present.

### T2-8. Guided Tour section is only reachable while a Write-tab is active
- **Where:** `app.html` L7694 (`"Guided tour"` section-title). Lives inside the Write-tab sidebar region.
- **Fix:** Lift to a top-level menu or add it to the collapsible Shortcuts cluster so it's reachable from Design/Produce/Ship too.

### T2-9. Reader "📖 More by this author" link falls back to /shelf when no uid known
- **Where:** `app.html` L30985 — `imprintEl.href = ownerUid ? ... : '/shelf';`. Label still reads *"More by {authorName}"*. Dead-end feel when no uid is present and the shelf page opens unfiltered.
- **Fix:** When falling back, change the label to *"Browse more books"* or hide the button entirely; don't promise "more by Mira Ashe" and deliver the generic shelf.

### T2-10. "🩺 Export for support" sits adjacent to the Release button in the modal footer
- **Where:** `app.html` L37787.
- **Why:** Equal visual weight next to Publish/Unpublish; an edge-case diagnostic that will have 0.1% usage is given 33% of the final-row real estate.
- **Fix:** Tuck under a tiny icon-only button, or move it into a `<details>` labelled *"Help / troubleshooting"*.

### T2-11. Release-modal "Public URL slug" field renders prominently for free users who can't edit it
- **Where:** `app.html` L36681-L36693. For free-tier the slug input is enabled visually and only becomes disabled per the sub-text; the Press upsell link is small and inline.
- **Fix:** For free users, show the auto-generated slug as read-only chip (not an input), with a small *"Customize this on Indie or Imprint →"* nudge. Removes a dead field from the fill order.

### T2-12. The release-modal "Access" picker is below Title/Author/Description + URL slug
- **Where:** The fill order is Title → Author → Description → URL slug → Access. "Public & free vs Paid vs Private link" determines what fields show downstream; it should drive the modal, not come after four shared fields.
- **Fix:** Move Access directly after Title/Author (keep Description after Access). Then the paid-only + shelf-only fields can reveal themselves cleanly based on the choice.

### T2-13. "Review Folio" button looks like a bribe
- **Where:** `app.html` L6541-L6549. Button copy: *"Review Folio / Earn a free 24h Featured Boost"* with the Boost line in filled accent orange.
- **Why:** The accent line is the loudest text in the entire sidebar. Trial-tester psychology: this reads as a cash-for-stars prompt, which may undermine the review's credibility when quoted on the welcome page.
- **Fix:** Keep the button; soften the Boost line (hint-coloured, non-bold) and relabel to *"Thanks: a free 24h Featured Boost"* so the gesture reads as appreciation rather than payment.

### T2-14. Attestation checkbox box is emerald-coloured but required — easy to mistake for a success state
- **Where:** `app.html` L37763-L37771. Green border + green-tinted background on a *checkbox* that must be ticked to publish.
- **Why:** Emerald is the universal "done/success" cue in the rest of the UI (publish button, LIVE badge, saved indicator). An unticked emerald box reads as "already handled, move on."
- **Fix:** Use neutral border + a prominent *"Required to release"* label; swap to emerald only once the box is ticked.

### T2-15. Help/FAQ, Guided Tour, Tutorials — three unrelated routes
- Help + FAQ (`app.html` L6522) opens `/help/` in a new tab, inside the collapsible Shortcuts panel.
- Tutorials (L7954) opens `/help/tutorials/` as a bottom-strip chip.
- Guided tour (L7694) is an in-app overlay inside the Write tab.
- **Fix:** Unify under one Help menu (icon in the header), with three ordered actions: *"Watch tutorials"* / *"Start guided tour"* / *"Help + FAQ"*.

## 4. Priority Tier 3 — polish for later

### T3-1. App header subtitle doesn't mention Narrate
- `app.html` L6431: *"Format · Export · Collaborate — PDF · EPUB · MD · and more"*. The homepage sells Narrate as a top-four feature; the app subtitle omits it.
- **Fix:** *"Write · Design · Narrate · Release — PDF · EPUB · MP3 · and more"*.

### T3-2. Hero stat "folios on the Shelf" wording is Folio-house jargon on a cold page
- `index.html` L825. A visitor who's never seen the word *folio* reads a stat called *"folios on the Shelf"* above the lede that explains what a folio is.
- **Fix:** First-fold stat should be *"Books on the Shelf"*; keep the word *folio* for signed-in surfaces.

### T3-3. Compare table isn't horizontally scrollable on narrow viewports
- `index.html` L1206 — `.compare` has `overflow:hidden`, inner table is 5 columns of 14px font. On a 375px phone the table will clip.
- **Fix:** Wrap in `<div style="overflow-x:auto">` or change `.compare { overflow-x:auto }`.

### T3-4. The sidebar's dark-mode toggle is a tiny ☽ in the header, invisible to new users
- `app.html` L6432-L6434. Night-mode is a common onboarding sanity-restore; the control is 14px grey-on-grey.
- **Fix:** Keep the compact control but add a `title` that reads *"Switch to dark mode (☀/☽)"* with the current state echoed.

### T3-5. Shelf author CTA strip and header both carry "📚" — three on one page
- `shelf.html` L255 brand, L367 series divider, L326 Browse Series button all show 📚. Readers pattern-match on the icon; a page with three bookshelf glyphs confuses the eye.
- **Fix:** Keep 📚 on the brand only; use 📖 for Browse Series or drop the icons entirely from the two sub-elements.

### T3-6. Admin "Shelf moderation" and "Guild moderation" share 🛡
- `admin/index.html` L109 and L144 both use 🛡. Admin-only, low stakes, but a second's hesitation each visit.
- **Fix:** 🛡 for Shelf moderation (consistent with "content safety"); 🤝 or 🏛 for Guild moderation (people-first).

### T3-7. "Vendor connections" is sidebar-level but useless for free users
- `app.html` L7542. Shown to every signed-in user; a free user with no paid folios will open it, see empty state, and bounce.
- **Fix:** Hide until the user has at least one paid folio, or convert to a sub-item inside the Release modal's paid section.

### T3-8. Imprint has two "Customize" entry points at once for owners
- Floating `#customizeToggle` (L1127) AND header-area owner CTA (L585-595). Opening the first scrolls past the second.
- **Fix:** Keep one entry per surface — floating pill is probably enough.

### T3-9. Guild "My listing" doesn't badge the user if they've already saved
- `guild/index.html` L122 — tab reads *"My listing"* regardless of whether a listing exists. Would help first-time users to distinguish *"My listing (empty)"* from *"My listing (live)"*.
- **Fix:** Suffix a small badge (green dot) when the listing is published.

### T3-10. Press FAQ "Payment security" is below "What's Perpetual pricing?" — buried
- `press/index.html` L326. Payment-security questions block conversion; they shouldn't be the next-to-last FAQ.
- **Fix:** Reorder: Free stays free · Cancel · Payment security · Boost stacking · Pre-sub Boost · Perpetual · Naming.

## 5. Vocabulary consistency table

| Concept | Where it drifts | Recommended canonical term |
|---|---|---|
| Publish online | *Release* (sidebar, toolbar, modal title) vs *Publish* (modal CTA, release doc field) vs *Ship* (tab name) | **Release** (verb + button) |
| Four-stage pipeline | *Write/Format/Narrate/Release* (homepage features) · *Draft/Set type/Narrate/Release* (how-it-works) · *Write/Design/Produce/Ship* (app tabs) | **Write · Design · Produce · Release** |
| Marketplace page | *The Folio Shelf* · *The Shelf* · *the Shelf* · *shelf* | **The Folio Shelf** (first use), **the Shelf** (thereafter) |
| Customize action | *Customize imprint* · *Customize this imprint* · *Customize my imprint* | **Customize imprint** |
| Project settings tab | *Folio* (☁ icon) sub-tab under Ship | **Settings** or **This folio** |
| Primary content unit | *folio* (author surfaces) · *book* (reader surfaces, homepage) | **Folio** when speaking to authors, **book** when speaking to readers |
| Press tier | *Press subscription* · *Folio Press* · *Press* | **Folio Press** (first use per page), **Press** (thereafter) |
| Imprint pro feature | *"coming soon"* on homepage · live on press page (custom subdomain) | Decide once, mirror |
| Taxonomy genres | Different lists in Guild vs Shelf vs Release | Share `docs/folio-taxonomy.json` everywhere |
| Narration section | *Narrate* (homepage) · *Produce* (app tab) · *Audio* (internal id `switchTab('audio')`) | **Produce** (tab name) + "Narrate" (verb in copy) |

## 6. Notes on mobile responsiveness

Not deep-dived, but these jumped out while reading markup:

- **Homepage compare table** (`index.html` L1206) has `overflow:hidden` and no horizontal scroll — 5 columns of 14px text will clip under ~720px. Add `overflow-x:auto`.
- **Homepage pricing tier cards** use `repeat(auto-fit, minmax(280px, 1fr))` which is fine, but each tier's CTA button sits at natural flow — on narrow screens tiers stack and the "Most flexible" ribbon on Indie overlaps the next tier's top. Check `.press-tier.featured::before` at ~400px.
- **App.html sidebar** is fixed-width (not inspected in full but structure implies desktop-first). On <700px the sidebar + preview likely cannot both fit; verify a mobile toggle exists before shipping tutorial that mentions "the sidebar on the left".
- **Release modal** is `max-width:560px; width:94%` — fine for width, but with 60+ fields and `max-height:92vh` the sticky Publish footer takes a chunk of a mobile viewport. On a 667pt-tall phone the usable scroll area is ~500px; verify fields don't crush.
- **Shelf tag-filter row** (`shelf.html` L338-L351) uses `flex:1; min-width:200px` on both inputs with the parent at `max-width:900px` — on narrow screens the labels wrap underneath their inputs, which is fine, but the 🏷/🚫 icons are the only cue which input is which; verify at 360px they stay legible.
- **Guild tabs row** (`guild/index.html` L119-123) with counts (`<span class="count">`) wraps awkwardly below ~400px; the *"My listing"* label has no count span so flex alignment goes uneven.
- **Imprint customize drawer** (`imprint/index.html` L1129+) — many URL/image inputs; verify on mobile that *Hero image URL* / *Wallpaper URL* fields don't require sideways swiping to see the Save button.
- **Admin tiles** use `grid-template-columns: repeat(auto-fill, minmax(…))` style; admin is desktop-only use so low priority.
